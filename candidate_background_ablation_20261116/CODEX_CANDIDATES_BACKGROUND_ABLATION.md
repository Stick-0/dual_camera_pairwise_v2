# Candidates의 배경 결합과 Essential 초기화 효과를 분리하는 실험 지침

작성일: 2026-11-16 (한국시간)

현재 저장소에 구현된 듀얼 카메라 로봇 포즈 추정 방법을 대상으로, Candidates 방식에서 **최종 배경 결합 항의 효과**와 **essential matrix 기반 초기화의 효과**를 분리하는 통제 실험을 구현하고 실행하라. 설계 제안에서 끝내지 말고, 새 코드·실행 명령·실제 결과·분석 보고서까지 작성하라.

먼저 `CURRENT_IMPLEMENTATION_REPORT.html`과 실제 코드·설정을 대조하라. 보고서 기준 확인 대상은 `pairwise/solver.py`, `candidates.py`, `geometry.py`, `matching.py`, `evaluation.py`, `runtime.py`와 실행 설정이다. 경로와 함수명은 저장소에서 확인하고, 과거 문서의 시간 누적 방식으로 되돌아가지 말라.

## 1. 반드시 유지할 조건

- 작업 시작 전에 존재하던 코드·설정·체크포인트·결과·캐시는 수정·삭제·덮어쓰기하지 않는다. `candidate_background_ablation_20261116/`처럼 아직 없는 새 디렉터리에만 코드와 결과를 작성한다. 기존 모듈은 읽기 전용으로 재사용하고, 필요한 solver 변경은 새 어댑터 또는 출처를 명시한 별도 모듈로 구현한다.
- 로봇 관측 모델과 RoMa V2의 구조·가중치를 유지한다. 재학습·미세조정·새 후보 생성은 하지 않는다.
- 카메라 2대와 로봇 베이스는 고정되고 관절은 움직인다. 각 영상의 촬영 시각에 대응하는 q1, q2와 기존 FK를 사용한다.
- 각 영상쌍을 독립적으로 추정한다. 이전 프레임 포즈·대응 누적·고정 포즈 평균·평가용 외부 변환을 추정에 사용하지 않는다.
- 정확한 후보 좌표·support·valid mask·후보 ID·관절각·카메라 파라미터를 네 조건에서 공유한다. 기존 raw 관측·매칭 캐시가 검증되면 그대로 재사용한다.
- 원본 파일 목록·해시를 전후 비교한다. import가 원본 경로에 캐시를 쓰지 않도록 `PYTHONDONTWRITEBYTECODE=1` 등으로 출력 위치도 관리한다.

## 2. 주 실험: 초기화 2종 × 배경 결합 2종

모든 조건의 로봇 관측 항은 동일한 Candidates 혼합 우도이다. A는 base→camera1, G는 camera1→camera2이며 두 로봇 포즈는 A, GA이다.

| ID | 포즈 초기화 | 본 최적화의 배경 항 | 의미 |
|---|---|---|---|
| R0 | 로봇 단안 포즈에서 초기화 | OFF | Candidates의 직접적인 No-cross 대조군 |
| R1 | R0와 정확히 같은 초기 A, G | ON | 같은 초기값에서 배경 결합 추가 |
| E0 | Essential 기반 포즈 초기화 | OFF | 배경 기하를 초기값에만 사용 |
| E1 | E0와 정확히 같은 초기 A, G | ON | 같은 E 초기값에서 배경 결합 추가 |

주 통제 실험은 **조건당 공동 최적화 시작점 1개**로 수행한다. 시작점 개수와 배경 비용에 따른 top-3 재선정이 요인에 섞이는 것을 막기 위한 설정이다. 초기화 생성 단계의 기존 단안 절차는 공통으로 한 번 실행해 공유한다.

기존 최대 3개 시작점의 `Mono-Candidates`, `Dual-Candidates` 결과는 별도 참고표로 보존한다. E1은 E 초기값만 쓰는 통제 조건이므로, 단안·E 경로를 함께 시도하는 기존 Dual-Candidates와 동일한 방법으로 표시하지 않는다. 이 실험은 기존 다중 시작점 전체 성능을 대체하는 평가가 아니다.

## 3. 초기값을 실제로 공유하는 구현

### R 초기화

현재 로봇 관측에서 얻은 카메라별 단안 초기해 T1, T2로 `A0=T1`, `G0=T2·inv(T1)`을 만든다. 둘 중 하나가 없으면 해당 R 초기화는 불가로 기록한다. 여러 proposal이 있으면 최종 결과를 보기 전에 정한 **로봇 항 비용과 안정적인 동률 처리 규칙**으로 하나를 선택한다. 배경 재투영 비용·평가 ADD·최종 gate 통과 여부로 R0/R1의 시작점을 따로 고르지 않는다.

### E 초기화

현재 배경 대응에서 essential matrix의 R과 이동 방향 d를 얻고, 기존 구현대로 `t=s·d`의 미터 척도를 로봇 재투영을 이용한 A와 log(s) 정제로 맞춘다. 이 초기화 생성 단계에서 유지되는 R/d는 본 최적화에 들어가면 모두 자유롭게 풀어야 한다.

E proposal도 배경 ON/OFF와 독립적인 사전 규칙으로 하나를 선정한다. E 생성에 실패하면 E0/E1을 `essential_init_unavailable` 등 명시적 상태로 남긴다. 이 통제 실험에서는 R 초기값으로 조용히 대체하지 않는다.

### 공유와 기록

- `pair_id, init_family, A0, G0, seed, proposal_id, selection_rule`을 한 번 저장하고 같은 배열을 OFF/ON에 복제한다. 배열 해시까지 일치해야 한다.
- 초기 책임도는 같은 후보와 같은 A0/G0에서 계산한다. 이후 EM 반복의 책임도는 각 방법의 포즈에 따라 갱신한다.
- 매칭·마스크·score/cycle/grid 선택으로 얻은 공통 2D 대응 집합을 고정한다. R1과 E1이 E-RANSAC inlier 선택 등으로 서로 다른 최적화용 대응 집합을 사용하지 않게 한다. 초기화 단계와 최종 최적화 관측 선택을 구분한다.
- ON의 P0는 해당 G0와 고정 대응에서 삼각측량한다. 삼각측량이 실패했다고 ON에만 다른 A0/G0를 주거나 다른 시작점을 찾지 않는다. 실패 원인을 별도 기록한다. 초기화에 따라 대응을 몰래 제거하여 목적함수 자체가 달라지지 않게 한다.
- R1도 배경점 초기화와 최적화에는 배경 대응을 사용한다. 명칭은 “essential 기반 포즈 초기화 미사용”이며 “배경 정보 미사용”이 아니다.

## 4. 배경 OFF는 배경의 잔여 제약까지 제거

배경 ON의 목적함수를 다음처럼 구분하라.

`L_on = L_candidates(A, GA) + L_robot_depth + L_background_reprojection(G, P) + L_background_depth(G, P)`

배경 OFF에서는 다음만 남긴다.

`L_off = L_candidates(A, GA) + L_robot_depth`

- OFF도 A와 G의 회전·이동 12변수를 모두 자유롭게 최적화한다. G나 E의 회전·이동 방향을 고정하지 않는다.
- OFF에서는 P를 변수 벡터에서 제거한다. 사용하지 않는 P와 zero-Jacobian 열을 남겨 수치적 rank 결손을 만들지 않는다.
- 배경 재투영 잔차, 배경 깊이 페널티, E/G prior, 초기 포즈 유지 항을 제거한다. 단안 포즈를 독립 관측처럼 다시 넣지 않는다.
- 두 조건의 파라미터화와 공통 로봇 EM 경로를 유지한다. 주 비교의 OFF만 A/B 독립 최적화로 바꾸지 않는다.
- OFF에서는 배경 대응 수·시차·hull·배경 재투영·배경 cheirality·기선 범위로 출력을 탈락시키지 않는다. 필요하면 진단값으로만 저장한다.
- 정보행렬은 활성화된 잔차로 다시 계산한다. ON은 기존처럼 P의 nuisance 방향을 제거한 포즈 정보, OFF는 P가 없는 로봇 포즈 Jacobian을 사용한다. 같은 포즈 단위 스케일과 적용 가능한 rank/condition 기준을 사용한다.

R0의 목적함수는 B=GA로 치환하면 두 단안 문제의 합으로 분리된다. E0 역시 최종 목적함수는 분리되지만 초기값에 두 영상 정보가 들어 있다. E0를 “완전한 단안 입력만 사용한 방법”으로 설명하지 않는다.

## 5. 공통 설정과 계산 예산

최신 구현의 Candidates 설정을 유지하라. 보고서 기준은 원래 voting 후보 8개, 후보 σ=2 px, outlier ε=0.05, 고정 support prior, 외부 EM 최대 10회, **각 내부 solve의** `max_nfev=60`이다. 유효 후보 필터·Gaussian 정규화·outlier 성분·전체 목적함수의 비용 증가 거부·종료 허용오차도 동일하게 유지한다.

ON의 배경은 기존 설정인 최대 80개 대응, σb=1.5 px, 2D 블록 Huber δ=3, λ=1을 유지한다. 실제 코드와 보고서가 다르면 차이를 먼저 기록하고 일관된 설정으로 고정한다. 개선 결과를 얻기 위해 조건별로 하이퍼파라미터를 조정하지 않는다.

같은 반복 상한이 같은 계산량을 뜻하지는 않는다. 실제 시작점 수, EM 횟수, 내부 nfev, 종료 사유, 초기화 시간과 최적화 시간을 저장한다. 공통 캐시 사용 시간과 추론·매칭을 포함하는 시간을 구분하고, 병렬 배치 시간을 단일 영상쌍의 online FPS로 바꾸지 않는다.

## 6. 실패·gate·평가 집합을 구분

기본 대상은 `UR_dual_2596`의 전체 2,596쌍, 5,192개 카메라 관측이다. 매칭 실패 때문에 R0까지 실행하지 않는 식의 공통 탈락 처리를 하지 않는다. 초기화·수치 풀이·로봇 유효성·배경 품질 실패를 구별해 기록한다. ON 실패를 OFF/단안 결과로 대체해 성공으로 세지 않는다.

각 결과에 다음을 분리해 저장한다.

1. 최종 gate 적용 전 유한한 포즈와 목적함수·잔차·깊이·정보량 진단.
2. 모든 조건에 적용 가능한 공통 포즈·로봇 유효성 검사 결과.
3. ON에만 적용되는 배경 품질 검사 결과와 최종 채택 여부.

주 결과는 전체 분모의 최종 채택 성능으로 보고하고, 공통 검사만 적용한 보조 결과도 함께 제시하여 배경 gate가 어려운 사례를 제거한 효과를 확인한다. 실제 코드의 검사와 reason을 먼저 조사해 이 구분에 매핑하며, 배경 OFF에 의미 없는 gate를 강제하지 않는다.

초기화 효과를 더 직접적으로 보기 위해 R/E 초기값 및 필요한 ON 초기화가 모두 준비되는 **공통 사전 적격 집합**도 저장한다. 이 집합은 최적화 전에 입력·초기화 상태만으로 정하며 최종 ADD나 최종 성공 여부로 고르지 않는다. 전체 2,596쌍 결과와 사전 적격 집합 결과를 각각 분모·제외 원인과 함께 보고한다.

## 7. 지표와 네 가지 비교

- ADD는 기존과 같은 촬영 시각별 FK 7점 지표, mm 단위로 계산한다. 평가용 외부 변환은 평가 단계에서만 읽는다.
- 전체 시퀀스의 ADD50과 AUC 분모는 5,192이다. 사전 적격 pair 집합 S만의 보조 결과는 2|S|를 분모로 한다. 각 평가 집합 안에서 실패를 분모에 유지하고 모든 유한 임계값에서 실패로 센다. AUC는 0–100 mm, 5 mm 간격 곡선의 사다리꼴 적분을 100 mm로 나눈 기존 정의를 유지한다.
- 평균·중앙값·P90 ADD는 유효 포즈 조건부로 표시하고 유효 개수를 함께 제시한다.
- paired ADD 차이는 동일 `pair_id, camera`에서 두 방법이 모두 유효한 교집합으로 계산하며 교집합 크기를 명시한다. 각 방법의 서로 다른 성공 집합 평균을 빼서 paired 효과라고 쓰지 않는다.
- 초기화 실패와 최종 실패를 포함한 전체 ADD50/AUC 차이도 같이 보고한다. 성공한 사례끼리만 비교해 전체 개선으로 확대하지 않는다.
- raw 입력 PCK, 사후 MAP 후보 PCK, 포즈 투영 PCK를 분리한다. 원래 후보 ID·좌표·γ·outlier 책임도도 저장한다. 주 성능 지표는 포즈 ADD이다.

필수 비교는 다음과 같다. ADD 차이는 뒤 조건에서 앞 조건을 뺀 값으로, 아래 표의 음수가 개선이다.

| 비교 | 해석 |
|---|---|
| R1 − R0 | 동일한 로봇 기반 초기값에서 배경 결합의 효과 |
| E1 − E0 | 동일한 E 기반 초기값에서 배경 결합의 효과 |
| E0 − R0 | 배경 기하가 초기값을 통해 주는 효과 |
| E1 − R1 | 배경 항이 있는 최적화의 초기화 민감도 |

네 방법 모두 유효한 동일 집합에서는 `(E1−E0)−(R1−R0)`도 계산하여 두 요인의 상호작용을 보조적으로 보고할 수 있다. ADD50/AUC는 양의 차이가 개선이다.

paired 평균 차이와 ADD50/AUC 차이의 95% 신뢰구간은 두 카메라를 한 pair로 묶은 시간 블록 bootstrap으로 산출하라. 모든 방법에 같은 재표집 인덱스를 적용한다. 원래 시간축에서 블록을 재표집한 후 사전 적격·공동 유효 마스크를 적용하며, 실패 행을 먼저 삭제해 시간 간격을 압축하지 않는다. 기본 블록 길이 1초, 반복 2,000회, seed 0을 사용하고 0.5초·2초에서 민감도를 확인한다. 이는 보편적인 독립성 보장값이 아니라 사전 지정한 분석 설정이다. 블록보다 긴 시간 상관이 보이면 그 한계를 기록한다. 5,192개 카메라 행이나 개별 키포인트를 독립 표본처럼 재표집하지 않는다. 원시 timestamp를 확보할 수 없으면 신뢰구간을 임의로 만들지 말고 미완료 사유를 남긴다.

## 8. 의미 있는 최소 검증

전체 실행 전에 다음을 확인하라.

- R0/R1 및 E0/E1의 초기 A0/G0 배열·관측 해시 일치.
- 초기 포즈를 고정한 OFF solve에서 배경 대응·P0만 바꿔도 포즈·로봇 목적함수·채택 상태가 바뀌지 않음. E0의 초기값 생성 단계 자체는 이 검사에서 제외한다.
- OFF에 배경점 변수·배경 깊이 항·E/G prior·배경 gate가 남아 있지 않음.
- 평가용 외부 변환을 교체해도 추정 결과는 변하지 않고 평가값만 달라짐.
- 실패가 ADD50/AUC 분모에서 빠지지 않음.

No-cross의 분리가능성을 확인할 필요가 있으면 같은 A0, B0=G0A0에서 독립 단안 최적화를 수행하는 작은 진단을 추가한다. A/G 공동 파라미터화와 유한 반복 때문에 생기는 수치 차이를 영상 결합 이득으로 해석하지 않는다. 큰 차이가 남을 때만 수렴·잔차를 추가 조사한다.

## 9. 실행 순서와 산출물

1. 실제 코드·입력·출력 경로를 확인하고 원본 보존 및 실험 설정을 기록한다.
2. 공유 관측과 초기값 캐시, 네 조건의 solver, 평가·보고 코드를 새 디렉터리에 구현한다.
3. 사전에 고정한 소수 pair로 위의 의미 검증과 실행 점검을 한다. 이 단계에서 GT로 설정을 고르지 않는다.
4. 문제가 해결되면 동일 설정으로 전체 2,596쌍을 실행한다. 일부 pair의 결과만으로 완료했다고 하지 않는다.
5. 기존 production 결과는 관측·설정·코드 출처를 확인한 뒤 별도 참고표에 포함한다. 캐시와 조건이 맞지 않으면 그 차이를 적고 같은 실험처럼 합치지 않는다.
6. 다음 산출물을 생성한다. 이름은 신규 파일의 제안이며 실제 저장소의 기존 파일을 뜻하지 않는다.

- `README.md`: 실행 환경, 새 기능의 사용법, smoke/full/evaluate 실행 명령.
- `experiment_config.yaml`, `manifest.json`: 공통 설정, 초기값 선정 규칙, seed, 코드·관측·가중치 해시, 원본 보존 확인.
- `initializations.jsonl`: R/E 초기값과 사전 적격 상태·실패 사유.
- `pair_results.jsonl` 또는 CSV: 네 조건의 포즈·후보 책임도·gate 전후 상태·실패 원인·반복 수·시간.
- `summary_metrics.csv`: 전체 및 사전 적격 집합의 네 조건 성능, 분모·유효 수·실패 수, 공통/최종 검사 기준 구분.
- `paired_comparisons.csv`: 네 가지 대비의 공동 유효 수, ADD 차이·개선/악화 비율, 전체 ADD50/AUC 차이·신뢰구간.
- `ablation_report.md` 또는 HTML: 실험 조건, 결과표, 실패 원인표, 시간, 해석과 한계.
- 그림: 실패 포함 ADD 곡선, 네 대비의 paired 차이, 개선·악화 사례의 실제 후보 및 포즈 시각화. 사례 선택 규칙을 기록하고 입력 후보와 포즈 투영점을 구별한다.

최종 보고서는 다음 질문에 실제 결과로 답해야 한다.

“같은 초기 포즈에서도 배경 결합을 넣으면 개선되는가? E 초기값만으로도 개선되는가? 두 효과가 함께 작용하는가? 배경 gate가 사례를 탈락시킨 효과와 구분되는가? 개선이 작은 경우 초기값·정보량·수렴·오대응 중 무엇이 원인인가?”

결과가 예상과 달라도 그대로 보고한다. 실행하지 않은 실험·확인하지 않은 수치·신뢰구간을 만들지 않는다. 데이터나 가중치가 없어 전체 실행이 막히면 가능한 구현·검증을 완료하고, 실제 실행 범위와 누락 입력·이어 실행할 정확한 명령을 명시하라.
